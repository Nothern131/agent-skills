# Slice Check — 功能切片检查制

把 AI 的一次大任务拆成若干个"功能切片"（≈ 人类工程师一天的工作量），逐片实现、逐片质量门、逐片确认。防止一口气写完再整体返工。

## 核心原则

> AI 写 1000 行 ≠ 人类写 1000 行。行数会骗人，时间无意义。
> 关键是**引入检查节律**：写一批就停下来做完整质量门检查。
> 切片是逻辑单位，不是行数单位。

## 触发条件

- 任务涉及 ≥3 文件 / 多模块 / 新功能
- 用户说"切片/分批/一天的量/按天做"
- 任务规模预估需要分 2-5 批才能完成

**不触发**：单文件小改（<10 行）、单文件中等改动（走交付模板即可）

## 执行流程

### 第 1 步：拆切片

接到中大型任务后，先输出**切片清单**：

```
【切片清单】{{任务名}}
共 {{N}} 片

切片1：{{功能名}}
- 边界：{{包含什么 / 不含什么}}
- 涉及文件：{{文件列表}}
- 验收标准：{{如何证明完成}}
- 体量：{{预估行数}}

切片2：...
```

**切片标准**（缺一不可）：
- ✅ 可独立运行（切片完成时有可运行的东西）
- ✅ 可独立审查（边界清晰，审查者不用看其他切片）
- ✅ 可独立回滚（坏了只影响本切片）
- ❌ 不按行数硬切——逻辑内聚优先，一个逻辑单元一个切片

**体量参考**：一个切片 ≈ 200-500 行等效工作量（含必要样板），太大再拆，太小合并。

### 第 2 步：逐切片实现

- 一次只做一个切片，不做下一个
- 每个切片完成后立即进入质量门，不做完质检不进入下一个

### 第 3 步：每切片质量门（4 项必过）

1. **运行验证**：代码能跑通（RunCommand 验证，输出命令+结果）
2. **codeguard 扫描**：8 维度 80 规则，Critical=0
3. **反证审查**：输入为空/超长/恶意？依赖挂了？假设"一定成功"？影响其他调用方？
4. **交付模板输出**（每次完成必用）：

```
【本次修改】切片 {{N}}/{{M}}：{{功能名}}
- 文件：{{列表}}

【验证证据】
- 命令：{{实际命令}}
- 结果：{{实际输出}}
- 是否通过：是/否

【反证审查】
- 最可能出问题的点：{{X}}
- 是否致命：是/否

【剩余风险】{{风险列表}}
【回滚方案】{{步骤}}
```

### 第 4 步：用户确认

- 每切片完成后**必须停下**，向用户汇报该切片成果 + 验收标准
- 等用户确认后才做下一个切片
- 用户可随时喊停

## 熔断

- 同一切片修复 ≥3 次仍不过 → 停止自动化，输出熔断报告
- 报告包含：已尝试路径、当前阻塞点、需要人工干预的理由

## 输出：切片进度表

每完成一片，更新进度表并在汇报中带上：

```
【切片进度】{{任务名}}
[✓] 切片1：{{功能名}} — 用户已确认
[✓] 切片2：{{功能名}} — 用户已确认
[ ] 切片3：{{功能名}} — 进行中
[ ] 切片4：{{功能名}} — 待开始
```

## 与现有系统的关系

- **与 Loop 的关系**：这是闭环验证的"批次化升级"——从"改到对为止"升级为"分批次交付，每批完整检查"
- **与 codeguard 的关系**：质量门第②步直接调用 codeguard skill
- **与交付模板的关系**：质量门第④步直接复用规则 3.3 交付模板
- **与 7 阶决策梯的关系**：切片内的实现仍需先爬 7 阶梯，切片制管的是批次节奏，不是实现细节
